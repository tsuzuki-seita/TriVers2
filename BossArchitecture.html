④ クラス別責務

MonoBehaviour

BossHead

Unityのライフサイクルと [SerializeField] パラメータの保持だけを担う。CreateSettings() でパラメータを BossModelSettings にまとめてVContainerに渡す。それ以外の処理は一切持たない。

Pure C#

BossModelSettings

Inspectorから調整可能なパラメータをまとめた不変データクラス。BossHead が生成し、VContainer 経由で BossModel コンストラクタに届く。

Interface

IBossStateContext

BossActions がモデルへアクセスするための窓口。BossModel の全機能を外部に公開せず、行動に必要な読み書きだけを絞って定義する。Atom がこのインターフェースにのみ依存することで、BossModel への直接依存を断ち切る。

Pure C#

BossModel

ボスの状態データを一元管理する。HP・位置・向き・現在のアニメーション状態・攻撃イベントを持つ。行動やAI判断のコードは一切持たない。

現行からの変化： HandleStateChanged・AttackSword・AttackMagic・Laugh・OnDamagedを撤去。アニメーション通知を ReactiveProperty<BossAnimation> 一本に統一。攻撃スポーンは Subject<T> で一発トリガー。
Pure C#

BossActions

アトミックな行動（原子）と、その合成（複合行動）を持つ。行動の「中身」のコードがここに全て集まる。private な Atom メソッドが再利用単位。public なメソッドが Atom を並べた複合行動。

現行からの変化： IBossState 実装クラス群（8ファイル）を廃止。BossModel にあった AttackSword・AttackMagic・Laugh をここに Atom として整理。
Pure C#

BossAIBrain

「次に何をするか」の判断だけを担う。BossActions のどのメソッドを呼ぶかを決め、CancellationToken で現在の行動を管理する。ダメージ割り込みの受け口もここ。

現行からの変化： BossModel.HandleStateChanged() 内 switch 文をここに移動。将来 ML-Agent や Behavior Tree へ置き換える際もこのクラスだけ差し替える。
MonoBehaviour

BossPresenter

Model の Observable を View の更新メソッドに繋ぐだけ。ロジックなし。

現行からの変化： 各ステートへの直接参照（stateController.idleState.IdleBool 等）を廃止。BossModel.Animation 一本を Subscribe するだけになる。ダメージ受付は CollisionSource を Subscribe して BossAIBrain.InterruptWithDamage を呼ぶだけ。
MonoBehaviour

BossView

Animator・HP スライダー・オーラエフェクト・攻撃プレハブのスポーンなど、見た目の更新だけを担う。

現行からの変化： 「You Win!」表示などゲーム結果ロジックを撤去。別のゲーム管理クラスが担う。
